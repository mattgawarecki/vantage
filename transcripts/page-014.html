Design decisions & trade-offs

  • Syntactic-only analysis (ts-morph, no type-checker program). Chose interactivity over precision — skips the expensive TS program build, so ~1900-file jitsi analyzes in ~4s. Cost: no type resolution → signal detection is structural/heuristic, not type-aware.
  • dependency-cruiser for the import graph instead of hand-rolling resolution. Get tsconfig-paths + dynamic-import handling for free; pay a heavy dep + adapting its output. First-party filter drops node_modules, ../ escapes, .d.ts, tests.
  • Depth = multi-source BFS from detected entrypoint(s), dynamic edges traversed, unreachable = null (off-trail). Directly serves "orient relative to a reference point." Trade: depth is import distance, not runtime/call distance — an approximation.
  • "Interesting" = 5 curated, gated signals (high-fan-in, complex-state, boundary-crossing, dynamic-import, recency) rather than one score. Gates encode your edge cases: simple utils excluded (high-fan-in needs loc≥30 && branches≥3), externals don't count. Trade: heuristics miss interesting-but-unmatched code, and risk false positives (e.g. fetch detection).
  • Percentile-rank scoring over signal-bearing files only (zero-signal = 0). Stops boilerplate zeros from inflating ranks. Trade: scores are relative within a repo, not absolute/comparable across repos.
  • Recency self-skips on uniform mtimes (fresh clones/snapshots). Honest — refuses to emit a garbage signal. Cost: invisible on the deployed playground snapshot.
  • LLM context: explain vs ask asymmetry. explain sends a window centered on the marker (±6, numbered) → precise. ask head-truncates the file at 6000 chars → cheap but breaks on large files (the documented limitation). Adaptive thinking; opus default, sonnet for cost; explain cached.
  • Orienteering metaphor as the product surface (summit/elevation/markers/trails/difficulty). Makes an abstract graph legible to a newcomer. Risk: metaphor over substance — mitigated by keeping each mapping literal.
  • Playground security posture. PLAYGROUND=1 disables /analyze + /pick (can't repoint at host FS), path-containment on /file, single key as a host secret outside REPO_PATH, single-origin Caddy (no CORS). Trade: shared process-global key (fine for a few reviewers) vs refactoring locked code.
  • Visibility-first build (mock data → live swap) on npm-workspaces monorepo. Got UI in front early; cost some mock→live rework.
  • Scope locked to TS/React (per brief) → entrypoint heuristics tuned to Vite/React conventions (index.html script, src/main.tsx).

How we'd extend with more time

  • Semantic feature clustering — group files into features (import topology + names/embeddings), not just per-file signals.
  • Hot-path detection — flag critical/perf-sensitive paths; optionally fold in coverage/runtime traces to find actually-executed code.
  • Type-aware tier (opt-in) — real call graph + type-based fan-in for precision when speed isn't the constraint.
  • Fix ask retrieval — center the window on the referenced symbol; multi-file RAG over the repo instead of head-truncation.
  • Git-blame integration — "ask the original author"; churn as an additional signal.
  • Complexity heat map on the file tree + elevation gauge.
  • Per-session keys + rate limiting for a true multi-tenant public playground.
  • Remote git-URL ingestion (clone + analyze) instead of a local path.
  • VS Code extension — orientation in-editor.
  • Broader entrypoint detection — Next.js/Remix routing, more frameworks.
  • Persisted/cached analysis (currently in-memory) for very large repos.
  • Automated tests — deliberately skipped for the demo.
